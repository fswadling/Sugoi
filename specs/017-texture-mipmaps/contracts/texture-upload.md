# Contract: Texture Upload

Public surface changed by this feature. Only `render/Texture.fs`'s decode/upload
path changes; the sampler, materials, pipelines, and shaders keep their existing
contracts.

## Texture loader — `render/Texture.fs`

```fsharp
// Decode an image file into an R8G8B8A8Unorm SDL_gpu texture with a complete level
// chain (base image down to 1x1), generated once at load. Raises with `path` if the
// image cannot be decoded, normalised, or uploaded.
val load : device:Gpu.Device -> path:string -> Texture
```

### Guarantees

- The returned handle has `NumLevels = floor(log2(max(width, height))) + 1`
  (minimum 1), created with `Sampler | ColorTarget` usage (FR-001).
- Level 0 is the decoded image after normalisation to a 32-bit RGBA byte layout;
  magnified appearance is unchanged (FR-003, FR-004).
- Levels 1..n are generated by SDL in the upload command buffer, outside any pass
  (FR-002).
- Surface row pitch is removed, so the uploaded image is not skewed.
- Non-square and non-power-of-two images are supported (FR-005).
- Any failure — decode, conversion, or texture creation — raises, naming `path`
  (FR-007). There is no mip-less fallback.

## Texture helper — `render/Texture.fs`

```fsharp
// The complete chain length for a width x height image: floor(log2(max(w, h))) + 1,
// minimum 1. Pure; the only part of the load path testable without a GPU device.
val (private) mipLevels : width:int -> height:int -> uint32
```

If kept private, its arithmetic is still the one candidate for a headless unit
test; expose it as `mipLevels` if a test is wanted.

## Asset loader — `world/Assets.fs`

```fsharp
// Unchanged contract: decoded textures are memoised by absolute path, so a shared
// map is prepared once and every material samples the same completed chain (FR-008).
val (private) loadTexture : loader:Loader -> path:string -> Texture.Texture
```

## Rules

- No per-frame work is added: decode, normalisation, upload, and generation all run
  during asset loading (FR-008, SC-004).
- The sampler keeps its linear/linear/linear configuration; no pipeline or shader
  change is implied by returning a texture with levels.
- The GPU requirements (color-target usage; generation outside a pass; SDL ≥ 3.2)
  are satisfied inside `load`; callers see only a texture handle.
