# Feature Specification: Texture Mipmaps

**Feature Branch**: `017-texture-mipmaps`

**Created**: 2026-09-13

**Status**: Draft

**Input**: User description: "Fix the missing mipmaps: textures are created with a single level while the sampler samples mipmaps, so minification aliases and pays a bandwidth cliff. Give every loaded texture a complete mip chain generated once at load. (Written retrospectively — the change is already implemented in `render/Texture.fs`.)"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Minified surfaces render smoothly (Priority: P1)

When a textured surface is seen at a distance or at a grazing angle — where one
screen pixel covers many texels — it reads as a stable, smooth surface rather
than as crawling high-frequency noise. Fine detail in the source image fades out
with distance instead of breaking up into flicker.

**Why this priority**: this is the entire point of the feature. Without it, every
textured asset in a scene shimmers as the camera moves, which is most visible in
the large, detailed environment assets the game is built around.

**Independent Test**: load a scene with a detailed textured environment, move the
camera so surfaces pass into the distance and across grazing angles, and confirm
their appearance is stable (no shimmer/crawl) compared with a baseline that has
no mip levels.

**Acceptance Scenarios**:

1. **Given** a textured surface far from the camera, **When** the camera moves,
   **Then** the surface does not visibly shimmer or crawl.
2. **Given** a surface whose normal is near-perpendicular to the view (grazing
   angle), **When** it is rendered, **Then** its distant texels resolve to a
   stable averaged appearance rather than aliased noise.
3. **Given** the same texture viewed close up (magnified), **When** it is
   rendered, **Then** its base-level detail is unchanged from before this feature.

---

### User Story 2 - Every loaded texture is covered automatically (Priority: P2)

Whatever map a material uses — albedo, normal, metallic-roughness, emissive —
receives the same treatment, with no per-asset authoring and no manual step. A
texture is decoded from its source file, uploaded, and its levels are completed
by the renderer at load time.

**Why this priority**: coverage is what makes the fix real. The pipeline is
shared, so the value only lands if all maps go through it uniformly, including
optional maps and textures shared by several materials.

**Independent Test**: load a scene whose materials use the full range of map
types and source image formats (with and without alpha, non-square,
non-power-of-two); confirm each renders without shimmer and without any
per-asset preparation.

**Acceptance Scenarios**:

1. **Given** a texture referenced by several materials, **When** the scene loads,
   **Then** it is processed once and all users sample its completed levels.
2. **Given** an image whose decoder yields a non-RGBA pixel layout, **When** it is
   loaded, **Then** it is normalised so it renders with the correct colours and
   coverage.
3. **Given** a non-square or non-power-of-two image, **When** it is loaded,
   **Then** it still receives a complete level chain and renders correctly.
4. **Given** a scene using both textured and untextured materials, **When** it
   loads, **Then** the untextured placeholder remains valid and unaltered.

---

### Edge Cases

- An image whose dimensions are not powers of two (e.g. 1000×1000) still receives
  a complete chain down to 1×1.
- An image whose decoded rows carry padding (row stride wider than the pixel row)
  is uploaded without skew.
- An image with no alpha channel is normalised to opaque rather than dropping to
  transparent or misordering channels.
- A 1×1 placeholder texture (used for absent maps) has no chain to complete and
  must remain valid as-is.
- The same texture path referenced by multiple assets is processed once and
  shared, so load cost does not multiply with scene size.
- A decode, format normalisation, or level-generation failure surfaces loudly with
  the offending path rather than silently sampling a single level.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Every texture uploaded for sampling MUST be created with a complete
  mip chain — levels from the full-resolution image down to 1×1 — whenever its
  largest dimension exceeds one texel.
- **FR-002**: Levels beyond the base image MUST be generated by the renderer at
  load time; they MUST NOT be required to be authored into the asset files.
- **FR-003**: The base level MUST be the decoded image's pixels; magnified
  appearance MUST be unchanged from an upload without a chain.
- **FR-004**: Images whose decoded pixel layout is not 32-bit RGBA MUST be
  normalised to a single shared RGBA layout before upload, preserving colour and
  alpha.
- **FR-005**: Non-square and non-power-of-two images MUST be supported, receiving
  a chain sized to their largest dimension.
- **FR-006**: Sampled textures MUST be minified using the generated levels
  (trilinear filtering), while magnification continues to use the base level.
- **FR-007**: A texture that fails to decode, normalise, or generate levels MUST
  fail loudly, naming the source path.
- **FR-008**: Level generation MUST happen once per texture at load; it MUST NOT
  run per frame, and textures shared by several materials MUST be processed once.
- **FR-009**: Single-texel textures MUST remain valid without a chain.

### Key Entities *(include if feature involves data)*

- **Texture**: a decoded image uploaded for sampling, identified in the cache by
  its source path; carries its full level chain.
- **Mip chain**: the sequence of progressively halved levels from the base image
  down to 1×1, ending at the level chosen by the sampler for minified fragments.
- **Material**: a set of sampled maps (albedo, normal, metallic-roughness,
  emissive) plus factors; every non-absent map is a texture with a completed
  chain.
- **Placeholder texture**: the shared 1×1 map substituted for absent maps, which
  needs no chain.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Textured surfaces seen under minification show no visible shimmer
  or crawling as the camera moves (100% of textured materials in a loaded scene).
- **SC-002**: Every sampled texture with a dimension greater than one texel has a
  complete chain terminating at 1×1 (100% of loaded textures).
- **SC-003**: Magnified (close-up) appearance of every texture is unchanged from
  the mip-less baseline (no regression).
- **SC-004**: Texture preparation remains a one-time load cost; the per-frame
  render path gains no work and the frame budget for a loaded scene is not
  regressed.
- **SC-005**: No textured asset is left sampling a single level without either a
  complete chain or a loud failure (0 silent single-level textures).

## Assumptions

- The renderer's sampler is already configured to sample mip levels; only the
  levels themselves are missing.
- The graphics backend and its version support generating levels from an uploaded
  base image; where they do not, load fails loudly rather than falling back.
- Texture preparation happens at scene load, off the per-frame path, so its cost
  is acceptable in exchange for correct minification.
- Generated levels are sufficient for the visual goal; hand-authored chains are
  out of scope.
- Colour-space handling of the source images is unchanged by this feature; mip
  levels are generated in the same space as the base level.
- Alpha-tested and opaque materials both use the same chain; per-material level
  policies (e.g. alpha-aware generation) are out of scope.
