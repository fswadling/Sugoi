# Implementation Plan: Trigger Anchors

**Branch**: `100-trigger-anchors` | **Date**: 2026-10-17 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/100-trigger-anchors/spec.md`

## Summary

Add `Camera` and `Player` creation anchors for triggers, behind one `Add Trigger`
menu, with automatic anchor-informed names. The camera anchor copies the editor
camera's exact position; the player anchor uses the player's authored feet position
minus 0.1 m. Creation reuses the existing `spawnTrigger`/`TriggerCreate` path, the
shared anchor palette is generalised from the waypoint feature, and the existing
default radius/height, identity rotation, and unit scale are preserved.

## Technical Context

**Language/Version**: F# on .NET 10 (`net10.0`)

**Primary Dependencies**: Prime, SDL3-CS, the custom cimgui binding, JoltPhysicsSharp.
Existing editor modules `Spawning`, `Outliner`, `Selection`; existing world modules
`Zone`, `Entity`, `Systems`.

**Storage**: In-memory zone state (`SlotMap<Trigger>`) and the existing project
manifest. No new persisted field or format; automatic names ride the existing trigger
name.

**Testing**: xUnit over the headless `Spawning`/`Zone`/undo paths
(`dotnet test test/Sugoi.Tests.fsproj`). The menu is validated manually via
`quickstart.md`.

**Target Platform**: Linux desktop (SDL3 window, GPU rendering, editor UI).

**Project Type**: Single desktop application with an in-engine editor.

**Performance Goals**: Keep the existing 60 FPS gameplay target. The new code runs only
while the editor is open and touches tens of triggers per zone.

**Constraints**: Edit-mode authoring only; no play-mode stamping. No new command, no
new persisted field or format, no change to trigger detection, cue wiring, or authored
shape. Every creation is exactly one undo step. No floor/ground query for either
anchor.

**Scale/Scope**: A zone holds tens of triggers (existing fixed slot-map capacity). The
anchor palette is closed at Origin, Camera, Player.

## Phase 0: Research

Completed in [research.md](research.md). Key decisions:

1. Rename `WaypointAnchor` to `SpawnAnchor` and share the palette, labels, and
   availability between waypoints and triggers.
2. The camera anchor copies the camera's exact position; no ground query.
3. The player anchor uses the authored feet position minus 0.1 m; requires a live
   player.
4. Reuse `spawnTrigger`/`TriggerCreate`; `triggerAt` and `spawnTriggerAt` are thin
   anchor adapters.
5. Generalise the waypoint naming loop into one private helper used by both kinds.
6. One creation popup in the Outliner using the 099 bindings; no Inspector section and
   no chain gesture.
7. Headless tests plus the manual quickstart.

## Phase 1: Design

Completed in [data-model.md](data-model.md) and [quickstart.md](quickstart.md).

**Model rules**

- No new persisted field or format. `Trigger.Base.Name` carries the automatic name.
- Anchors: `Origin`, `Camera`, `Player`; `Camera` is always available in edit mode;
  `Player` requires a live designation.
- Trigger base position:
  - `Origin` -> zero;
  - `Camera` -> `camera.Position`;
  - `Player` -> player feet minus `Vector3(0, 0.1, 0)`.
- Identity rotation, unit scale, and the existing default radius/height.
- Names: `<Prefix> <lowest free positive n>` over live triggers with that prefix.
- Command: `TriggerCreate` only; `spawnTrigger` already selects and records it.
- Capacity: reuse `hasRoom`; refuse before mutating and record nothing.

**UI rules**

- Outliner: one `Add Trigger` button opens a popup over `spawnAnchors`; creation is
  disabled at capacity and `Player` is disabled without a live designation.
- The trigger rows and the Inspector are unchanged; triggers have no chain/extend
  gesture.

## Complexity Tracking

No constitution violations. The only refactor is the `SpawnAnchor` rename plus the
shared naming helper, both of which remove duplication rather than add abstraction.

## Implementation Outline

1. **Spawning**: rename `WaypointAnchor` to `SpawnAnchor` and the palette to
   `spawnAnchors`; update the waypoint call sites and tests. Extract the generic
   automatic-name helper and add the trigger name function. Add `anchorPosition`,
   `triggerAt`, and `spawnTriggerAt`.
2. **Outliner**: replace the trigger `Add Trigger` button with the creation popup.
3. **Tests**: player/camera placement, the 0.1 m offset, names and reuse, capacity,
   selection, independence, and undo/redo.
4. **Docs**: record trigger authoring in `docs/EDITOR_DESIGN.md`.
5. **Validation**: build, full suite, and the manual quickstart.
