# Implementation Plan: Actor and Prop Spawn Anchors

**Branch**: `101-actor-prop-anchors` | **Date**: 2026-10-17 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/101-actor-prop-anchors/spec.md`

## Summary

Add a shared `Spawn at` anchor selector to the Asset Browser. Actors and props can be
spawned at the origin, the editor camera, or the live designated player. Origin remains
the default. Camera placement uses the exact camera position and horizontal yaw only;
player placement copies the player's authored feet position and rotation. Spawns reuse
the existing `spawnActor`/`spawnProp` paths, keep their asset names, are selected, and
remain one undo step. The selected anchor lives in `EditorState`, so the shared anchor
vocabulary moves there from `Spawning`.

## Technical Context

**Language/Version**: F# on .NET 10 (`net10.0`)

**Primary Dependencies**: Prime, SDL3-CS, the custom cimgui binding, JoltPhysicsSharp.
Existing editor modules `AssetBrowser`, `Spawning`, `Selection`; existing world modules
`Zone`, `Entity`, `Systems`.

**Storage**: In-memory zone state (`SlotMap<Actor>`, `SlotMap<Prop>`) and the existing
project manifest. No new persisted field or format.

**Testing**: xUnit over the headless `Spawning`/`Zone`/undo paths
(`dotnet test test/Sugoi.Tests.fsproj`). The selector and asset buttons are validated
manually via `quickstart.md`.

**Target Platform**: Linux desktop (SDL3 window, GPU rendering, editor UI).

**Project Type**: Single desktop application with an in-engine editor.

**Performance Goals**: Keep the existing 60 FPS gameplay target. The selector and spawn
work run only while the editor is open.

**Constraints**: Edit-mode authoring only. No new command family, persisted field, or
format. No change to actor/prop asset semantics, cue addressing, or environment
loading. Every spawn is exactly one undo step. Camera placement performs no collision
query.

**Scale/Scope**: Actor and prop asset lists are small (tens of entries); a zone holds
tens of each kind at the existing fixed capacities.

## Phase 0: Research

Completed in [research.md](research.md). Key decisions:

1. Move `SpawnAnchor`/`spawnAnchors`/`anchorName` to `EditorState` and add
   `SpawnAt`; keep `anchorAvailable` in `Spawning`.
2. Camera placement: exact position, horizontal yaw only, identity yaw for a vertical
   view.
3. Player placement: authored feet position and rotation; live designation required.
4. Add `spawnActorAt`/`spawnPropAt` as transform adapters over the existing spawn paths.
5. Keep asset names; no automatic naming.
6. One shared `Spawn at` combo for both sections; disable it appropriately.
7. Headless spawn tests + manual quickstart.

## Phase 1: Design

Completed in [data-model.md](data-model.md) and [quickstart.md](quickstart.md).

**Model rules**

- No new persisted data. `EditorState.SpawnAt` is transient and defaults to `Origin`.
- Anchor transforms:
  - `Origin` -> zero/identity;
  - `Camera` -> `camera.Position` and yaw `atan2(forward.X, forward.Z)` about +Y;
  - `Player` -> authored feet position and rotation, or `None` without a live player.
- Spawns apply the anchor transform to the entity built from the asset name, keep unit
  scale and the asset binding, then delegate to `spawnActor`/`spawnProp`.
- Commands: `ActorCreate`/`PropCreate` only; no new command or runner.
- Capacity: reuse `hasRoom`; the Asset Browser disables when full.

**UI rules**

- One `Spawn at` combo above the asset sections, listing `Origin`, `Camera`, `Player`;
  `Player` is disabled when unavailable.
- Asset buttons spawn at the selected anchor; they are disabled when the anchor is
  unavailable or the kind is full.
- The selector is shared by Actors and Props; environments ignore it.
- The selector is transient: not undoable and not persisted.

## Complexity Tracking

No constitution violations. The only refactor is moving the anchor vocabulary to
`EditorState` and updating its call sites, which removes the compile-order obstacle
without introducing hidden global state.

## Implementation Outline

1. **EditorState**: move `SpawnAnchor`, `spawnAnchors`, and `anchorName` from
   `Spawning`; add `SpawnAt` defaulting to `Origin`.
2. **Spawning**: update signatures/references to the moved vocabulary; keep
   `anchorAvailable`; add `assetAnchorTransform`, `spawnActorAt`, and `spawnPropAt`.
   Use qualified `EditorState.Origin` / `EditorState.Camera` / `EditorState.Player`;
   do not `open EditorState` in `Spawning`, because its `Camera` case would shadow the
   `Camera` module used for the camera basis.
3. **Waypoint/trigger UI**: update `Outliner`/`Inspector` to the moved vocabulary.
4. **AssetBrowser**: add the shared `Spawn at` combo and route asset buttons through
   the anchor-aware spawn functions; combine anchor availability with capacity.
5. **Tests**: update existing anchor-case references; add actor/prop placement,
   orientation, vertical-camera, no-player, capacity, selection, and undo/redo tests.
6. **Docs**: record the interaction in `docs/EDITOR_DESIGN.md`.
7. **Validation**: build, full suite, and the manual quickstart.
